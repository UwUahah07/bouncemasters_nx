## 📖 О проекте

**Bouncemasters NX** — экспериментальный неофициальный порт Bouncemasters на Nintendo Switch. Проект загружает Android-версии библиотек Unity/IL2CPP и адаптирует их окружение к libnx и аппаратным API Switch.

> [!NOTE]
> Репозиторий является форком [ChanseyIsTheBest/bouncemasters_nx](https://github.com/ChanseyIsTheBest/bouncemasters_nx) и находится в активной разработке.

### Как устроен порт

Проект не включает исходный код или ресурсы игры. На старте загрузчик:

1. Находит папку с установленными файлами порта.
2. Проверяет наличие необходимых Unity-ресурсов.
3. Загружает и перемещает `libmain.so`, `libunity.so` и `libil2cpp.so` в память процесса.
4. Подключает совместимость для libc, JNI, Android SDK, OpenSL ES и Unity API.
5. Настраивает GLES3/EGL, сенсорный экран и контроллеры.
6. Запускает nativе-код Unity и отображает сцену игры.

## 🎮 Управление

Управление зависит от контекста экрана:

| Действие | Способ |
|---|---|
| Навигация в меню | Сенсорный экран / курсор |
| Перемещение курсора | Стик при включённом Pointer Input |
| Нажатия в интерфейсе | Сенсорный экран / кнопки контроллера |
| Управление в игре | Сенсорный экран и кнопки |
| Назад и выход | Системные действия Nintendo Switch |

Конкретные привязки могут изменяться вместе с внутренними патчами ввода и не являются финальными.

## 📦 Требования

### Для запуска

- Nintendo Switch с поддерживаемой средой homebrew.
- Nintendo Switch, запущенная в режиме **title override**: удерживайте `R` при запуске установленной игры.
- Достаточно свободного места на microSD-карте.
- Легально полученная копия Android-версии Bouncemasters.
- Собранный `openbonk_nx.nro`.

### Для сборки

- devkitPro и devkitA64.
- Переменная окружения `DEVKITPRO`.
- Следующие portlibs:
  - `switch-mesa`
  - `switch-libdrm_nouveau`
  - `switch-sdl2`
  - `switch-zlib`
  - `switch-libpng`

Linux и macOS:

```bash
dkp-pacman -S switch-mesa switch-libdrm_nouveau switch-sdl2 switch-zlib switch-libpng
```

Windows — в devkitPro MSYS2:

```bash
pacman -S switch-mesa switch-libdrm_nouveau switch-sdl2 switch-zlib switch-libpng
```

## 🚀 Установка

> [!IMPORTANT]
> Этот репозиторий **не содержит** APK, OBB, игровые `.so`-файлы, ассеты или другие элементы оригинальной игры. Ставить порт необходимо только из законно полученной копии.

На microSD карта ожидает такую структуру рядом с `.nro`:

```text
sdmc:/switch/openbonk_nx/
├── openbonk_nx.nro
├── libmain.so
├── libunity.so
├── libil2cpp.so
└── assets/
    ├── bin/Data/
    │   ├── globalgamemanagers
    │   ├── level0
    │   ├── boot.config
    │   └── Managed/Metadata/global-metadata.dat
    └── aa/
```

Общие шаги:

1. Соберите `.nro` или скачайте артефакт сборки.
2. Поместите `openbonk_nx.nro` в выбранную папку на карте памяти.
3. Из вашей копии извлеките:
   - `libmain.so`;
   - `libunity.so`;
   - `libil2cpp.so`;
   - папку `assets` из APK и, при наличии, объединённую папку данных из OBB.
4. Не переименовывайте обязательные файлы и сохраните структуру папки `assets`.
5. Запустите приложение через title override.

В ходе проверки загрузчик требует наличие как минимум:

- `assets/bin/Data/globalgamemanagers`
- `assets/bin/Data/level0`
- `assets/bin/Data/boot.config`
- `assets/bin/Data/Managed/Metadata/global-metadata.dat`

Если проверка не пройдена, загрузчик выведет объяснение на экране и запишет подробности в `debug.log` при включённом режиме диагностики.

## 🔧 Сборка

Клонирование:

```bash
git clone https://github.com/UwUahah07/bouncemasters_nx.git
cd bouncemasters_nx
```

Проверка окружения:

```bash
export DEVKITPRO=/opt/devkitpro
make
```

В результате появится:

```text
openbonk_nx.nro
openbonk_nx.elf
openbonk_nx.nacp
```

Очистка сборочной директории:

```bash
make clean
```

Полная параллельная сборка:

```bash
make -j$(nproc)
```

GitHub Actions в этом репозитории автоматически собирает проект через Docker-образ `devkitpro/devkita64` при каждом `push` и ручном запуске workflow.

## 🧩 Проверка staged-файлов

Makefile содержит цель для проверки, если в проекте есть подходящая папка staging-данных:

```bash
make check GAME=/путь/к/подготовленным/файлам
```

Команда запускает `tools/symcheck.py` и сравнивает staged-библиотеки с таблицами символов из исходников.

## ⚙️ Основные настройки

Основные параметры находятся в [`source/config.h`](source/config.h):

- принудительный GLES-путь;
- разрешение рендеринга;
- сенсорный ввод и курсор;
- звуковые параметры;
- размер GPU arena;
- размер области памяти для `.so` модулей;
- параметры диалогов и загрузки;
- режим диагностики;
- режим принудительного офлайн-входа.

Для обычного запуска достаточно оставить значения по умолчанию. Во время отладки можно включить `DEBUG_LOG`, но это заметно увеличивает нагрузку на SD-карту и может снижать FPS.

### Важные параметры отладки

```c
#define DEBUG_LOG 1
#define DEBUG_JNI_TRACE 1
#define BM_LOG_BUTTONS 1
#define TRACE_IO 1
#define TRACE_MMAP 1
```

Включайте их по одному и отключайте сразу после воспроизведения проблемы.

## 🩺 Устранение неполадок

### Игра запускается только в applet mode

Для этого порта нужен значительный объём памяти. Используйте **title override**:

1. Откройте Альбом или установите приложение через homebrew-среду.
2. Удерживайте `R`.
3. Запустите установленную игру.

### Unity не загружается или падает на старте

Проверьте следующее:

- папка данных расположена рядом с `.nro`;
- имена библиотек не изменены;
- структура `assets` сохранена;
- в APK и OBB нет несовместимых обновлений;
- в корне есть обязательные Unity-файлы;
- проект собран с теми же commit/build флагами.

### Нет ассетов

Загрузчик допускает отсутствующие необязательные SDK-файлы, но останавливается при отсутствии ключевых Unity-файлов:

```text
assets/bin/Data/globalgamemanagers
assets/bin/Data/level0
assets/bin/Data/boot.config
assets/bin/Data/Managed/Metadata/global-metadata.dat
```

### Нет звука

Это известная незавершённая область порта. Для поиска причины проверьте `debug.log` и параметры OpenSL ES в `source/config.h`.

### Частые падения

Попробуйте:

- обновить сборку;
- удалить старый `debug.log`;
- удалить устаревшие данные и повторно подготовить ассеты;
- запустить с включённым `DEBUG_LOG`;
- сохранить трассировку и модель падения для отчёта об ошибке.

### Где найти лог

По умолчанию лог записывается в папку запуска:

```text
sdmc:/switch/openbonk_nx/debug.log
```

## 🔍 Технические особенности

- Целевая архитектура: **AArch64 / ARM64**.
- Флаг сборки: `armv8-a+crc+crypto`, Cortex-A57.
- Загружаются ELF-модули Android с пользовательской relocation-логикой.
- Основные шины совместимости: SDL2, GLESv2, EGL, drm_nouveau.
- Используются собственные stubs для Android JNI и SDK API.
- В проекте предусмотрена индексирующая система Unity AssetBundle-путей.
- Поддерживается тач и HID-курсор через общий путь ввода.
- Для libil2cpp используется GC-bridge для встроенного сборщика мусора.
- Новый GPU-allocator выделяет память nouveau в отдельную область, чтобы уменьшить фрагментацию общей кучной памяти.
