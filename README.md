## 📖 О проекте

Этот репозиторий содержит **не саму игру Megabonk**, а файлы поддержки, необходимые для запуска её нативного порта на Nintendo Switch: загрузчик, слой совместимости с окружением Android/Unity, обработку ввода, графики, памяти и другие платформенные компоненты.

Репозиторий [`ChanseyIsTheBest/bouncemasters_nx`](https://github.com/ChanseyIsTheBest/bouncemasters_nx) использовался как источник подходящих файлов и технических наработок для поддержки запуска игры на Switch. **Этот проект посвящён Megabonk, а не переносу Bouncemasters.**

> [!NOTE]
> В исходниках и настройках могут оставаться старые названия, комментарии или идентификаторы от проектов, из которых переносились отдельные технические решения. Они не определяют назначение этого проекта и могут постепенно заменяться.

Репозиторий не содержит исходного кода Megabonk, игровых библиотек или ресурсов. Для запуска пользователь самостоятельно подготавливает нужные файлы из собственной копии игры.

## 🧭 Что находится в репозитории

Проект сосредоточен на платформенной части запуска, в том числе:

- загрузке нативных библиотек игры;
- подготовке среды выполнения Unity/IL2CPP;
- адаптации необходимых Android API и JNI-вызовов;
- настройке графического пути Switch через GLES/EGL;
- обработке ввода Nintendo Switch;
- подготовке путей к ресурсам и пользовательским данным;
- настройке памяти, GPU-буферов и диагностики;
- сборке homebrew-приложения `.nro`.

Это вспомогательная инфраструктура для нативного порта, а не самостоятельный релиз игры или дистрибутив с игровыми файлами.

## 📦 Требования

### Для запуска

- Nintendo Switch с настроенной средой homebrew.
- Запуск в режиме **title override**: удерживайте `R` при запуске установленной игры.
- Собранный файл `.nro`.
- Совместимые библиотеки и ресурсы Megabonk из вашей собственной копии.

Порт требует больше памяти и системных разрешений, чем обычно доступно приложению в applet mode. Если приложение сообщает о нехватке памяти или необходимых системных вызовов, используйте title override.

### Для сборки

- devkitPro и devkitA64.
- Настроенная переменная окружения `DEVKITPRO`.
- Switch portlibs:
  - `switch-mesa`
  - `switch-libdrm_nouveau`
  - `switch-sdl2`
  - `switch-zlib`
  - `switch-libpng`

Установка пакетов в Linux/macOS:

```bash
dkp-pacman -S switch-mesa switch-libdrm_nouveau switch-sdl2 switch-zlib switch-libpng
```

В Windows запустите команду из devkitPro MSYS2:

```bash
pacman -S switch-mesa switch-libdrm_nouveau switch-sdl2 switch-zlib switch-libpng
```

## 🔧 Сборка

Клонируйте репозиторий и перейдите в его каталог:

```bash
git clone https://github.com/UwUahah07/bouncemasters_nx.git
cd bouncemasters_nx
```

Задайте п��ть к devkitPro, если он ещё не настроен, и соберите проект:

```bash
export DEVKITPRO=/opt/devkitpro
make -j$(nproc)
```

Makefile собирает homebrew-приложение `openbonk_nx.nro`. Для обычной сборки без параллелизма используйте `make`, для очистки результатов сборки — `make clean`.

> [!TIP]
> GitHub Actions выполняет сборку при `push` и при ручном запуске workflow. Готовый `.nro` загружается как workflow artifact с именем `nro`.

### Проверка библиотек

Если в рабочем окружении есть `tools/symcheck.py`, можно проверить staged-библиотеки и таблицы импортов:

```bash
make check GAME=/путь/к/подготовленным/файлам
```

## 🚀 Подготовка и запуск

Сборка не включает игровые библиотеки или ресурсы. Подготовьте данные из собственной копии Megabonk. В текущей конфигурации загрузчик ожидает библиотеки с такими именами:

```text
libmain.so
libunity.so
libil2cpp.so
```

Структура каталога с данными должна соответствовать ожиданиям текущей сборки. Точный состав файлов зависит от версии игры; при запуске ориентируйтесь на сообщения загрузчика и актуальную конфигурацию проекта.

Общий порядок:

1. Соберите `.nro`.
2. Скопируйте `.nro` на microSD-карту.
3. Подготовьте требуемые библиотеки и ресурсы из собственной копии Megabonk.
4. Разместите их в каталоге, доступном загрузчику, сохранив имена и ожидаемую структуру.
5. Запустите `.nro` через title override.
6. Если запуск не удался, проверьте сообщение на экране и `debug.log`, если диагностика включена.

> [!CAUTION]
> Не распространяйте APK, OBB, игровые библиотеки или ресурсы вместе с этим проектом.

## 🧰 Настройка и диагностика

Большинство параметров сборки находится в `source/config.h`. Там настраиваются параметры диагностики, графики, аудио, ввода, памяти и совместимости.

Для диагностики предусмотрены флаги, включая:

- `DEBUG_LOG` — расширенный лог загрузки;
- `DEBUG_JNI_TRACE` — подробная трассировка JNI;
- `BM_LOG_BUTTONS` — события кнопок;
- `TRACE_IO` и `TRACE_MMAP` — трассировка файлового ввода-вывода и отображения памяти.

Включайте только необходимые флаги: подробное логирование может снизить производительность и увеличить число записей на SD-карту. После сбора нужной информации верните их в исходное состояние.

### Если приложение сразу закрывается

1. Убедитесь, что используете title override, а не applet mode.
2. Проверьте, что `.nro` и требуемые данные доступны на карте памяти.
3. Проверьте совместимость файлов игры с текущей версией загрузчика.
4. Пересоберите проект после обновления исходников.
5. Сохраните `debug.log` и приложите его к отчёту о проблеме.

### Если нет звука

Отсутствие звука известно для текущего состояния порта и не обязательно означает ошибку установки. Работа над аудиоподсистемой продолжается.

### Если наблюдаются вылеты или просадки FPS

Порт всё ещё в разработке. Для отчёта укажите версию игры и сборки порта, режим запуска, режим консоли (handheld/docked), шаги для воспроизведения и лог.
